# AI Renovation Platform — прототип

Этап 1: скелет веб-приложения и мастер создания проекта (шаги 0–7 из документа
«Вопросы клиенту и путь пользователя»).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run dev:server # API на http://localhost:8787 (дизайн от ИИ), во втором терминале
npm test           # тесты доменной логики
npm run typecheck  # проверка типов во всех пакетах
npm run build      # production-сборка веба
```

### На сервере

Нужен Node.js 22 или 24 (LTS). Ключ — в `apps/server/.env` (`ANTHROPIC_API_KEY=...`).

```bash
npm ci
npm run build                 # собирает сайт в apps/web/dist
PORT=8787 npm start           # сайт и API на одном порту: http://сервер:8787
# постоянная работа и автозапуск, например через pm2:
#   npm i -g pm2 && pm2 start npm --name ai-renovation -- start && pm2 save && pm2 startup
```

Переменные окружения: `PORT` (по умолчанию 8787), `HOST` (0.0.0.0), `DESIGN_RATE_LIMIT_PER_HOUR` (30 запросов к ИИ в час с одного IP).

За nginx (для домена и HTTPS) обязательно:

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  # лимит запросов считается по IP
    proxy_read_timeout 300s;      # дизайн кухни-гостиной и распознавание идут до 3 минут
    client_max_body_size 32m;     # файлы планов
}
```

Сайт открыт всем, у кого есть адрес, и каждый запрос к ИИ тратит ваш ключ. Для закрытого теста добавьте
в nginx пароль (`auth_basic`) или ограничьте доступ по IP. Проекты хранятся в браузере пользователя, на сервере — ничего.

## Структура

```
packages/domain/   Доменная модель и бизнес-правила (чистый TypeScript, без UI).
                   Переиспользуется в будущем мобильном приложении.
  types.ts         Проект, геометрия плана, стены, жильцы, пожелания
  walls.ts         Статусы стен: подсказки по толщине, запрет сноса несущих/неизвестных
  wizard.ts        Шаги мастера, обязательные поля, шкала точности
apps/web/          Веб-приложение: React + Vite + Ant Design + Zustand
  features/wizard/ Мастер и его шаги
  features/plan/   2D-отрисовка плана (SVG) из геометрии
  store/           Состояние (сейчас localStorage, далее — API)
  demo/            Демо-план для прототипа (до подключения распознавания)
```

## Что работает и что нет

Работает: все 9 шагов мастера, ветки вопросов по цели, разметка стен кистью,
инженерные точки на плане, шкала точности, сохранение и просмотр проектов.

Шаг «Отделка» (по созвону 09.11.2026, `docs/meeting-2026-11-09-finishes.md`): выбор по каждой комнате
карточками-картинками — потолок, освещение, стены, пол, двери, сантехника, мебель, шторы; розетки и
светильники для всей квартиры. Правила в `packages/domain/src/finishes.ts`: санузел — стены краска/плитка,
пол только плитка; классика — только двери с наличниками и рамки на стенах; шторы — только в комнатах
с окнами; копирование отделки из другой комнаты. Иллюстрации на карточках — схемы, не фото материалов.

Не реализовано (честно помечено в интерфейсе):
- бэкенд и аккаунты — данные хранятся только в браузере (localStorage);
- варианты перепланировки, смета, ручной редактор плана (вместо него — описание словами).

Пороги толщины стен и веса шкалы точности — гипотезы, их нужно уточнить.

## Распознавание плана (Claude)

Шаг «План»: файл (JPG, PNG, WebP, PDF до 15 МБ) → кнопка «Распознать план»; вариант «Описать словами» —
план строится по текстовому описанию. Эндпоинт `POST /api/plan/recognize` (`apps/server/src/planReader.ts`).

- Модель читает план и возвращает комнаты контурами (мм, по осям стен), двери и окна точками, толстые
  внутренние стены и список сомнительных мест.
- Стены, наружные/межкомнатные, привязку проёмов и проверки строит код (`packages/domain/src/planRecognition.ts`):
  координаты стягиваются к общим линиям, ищутся перекрытия комнат, несовпадение с подписанной площадью
  (в чистоте), окна не на наружной стене, комнаты без двери. При замечаниях модель один раз исправляет ответ.
- Шаг «Размеры»: оригинал рядом с распознанным планом, сомнительные места, правка названий и типов комнат,
  «Исправить по уточнениям» — повторное распознавание с текстом клиента.
- Новый план сбрасывает отделку, стены и инженерные точки: они привязаны к комнатам старого плана.
- Ручной прогон: `cd apps/server && npx tsx scripts/try-plan.ts план.png ["уточнения"]` или `--text "описание"`.
  Около 1–2 минут и ~$0,1–0,2 за план. Фото больше 2400 px по длинной стороне браузер уменьшает перед отправкой.
- Демо-квартира остаётся только для варианта «Нет плана».

## Дизайн от ИИ (Claude)

На странице проекта блок «Дизайн от ИИ»: для каждой комнаты Claude (`claude-opus-5-5`) проектирует
расстановку мебели, свет и палитру по плану, выбранной отделке, стилю и жильцам. Результат рисуется в 3D
(three.js, `apps/web/src/features/design/RoomScene3D.tsx`).

- Ключ: скопируйте `apps/server/.env.example` в `apps/server/.env` и вставьте `ANTHROPIC_API_KEY`. Ключ есть
  только на сервере, во фронтенд он не попадает; `.env` в git не коммитится.
- Модель проектирует, код проверяет: `packages/domain/src/design.ts` — бриф для модели и проверка ответа
  (мебель внутри стен, не пересекается, не мешает дверям и окнам, не закрывает стояки, вся выбранная мебель
  на месте, свет соответствует выбору). При замечаниях модель один раз получает их на исправление; то, что не
  исправлено, показывается клиенту.
- Каждая генерация — платный запрос; лимит по умолчанию 30 генераций в час на IP (`DESIGN_RATE_LIMIT_PER_HOUR`).
- Это схематичная 3D-модель (мебель блоками в реальных размерах), не фотореалистичный рендер.

### План размещения мебели

Перед 3D: вкладка «Вся квартира» в блоке «Дизайн от ИИ» — лист как у дизайнера (образец — рабочие чертежи
ЖК «Леополь Таун»). Мебель сверху условными обозначениями, синие привязки к чистовым стенам и габариты (мм),
экспликация помещений, спецификация, «Печать / PDF» (A3). Кнопка «Спроектировать (N)» по очереди проектирует все
недостающие комнаты. Во вкладке комнаты — «План мебели | 3D», по умолчанию план. Сборка листа и привязки:
`packages/domain/src/furniturePlan.ts`, чертёж: `apps/web/src/features/design/FurniturePlanDrawing.tsx`.

### Каталог товаров

Claude выбирает конкретные товары из каталога (`apps/server/data/catalog.json`); размеры, цвет и название
подставляются из каталога, а не из ответа модели. Сейчас подключён **демо-каталог** — обезличенные товары с
типовыми размерами, без брендов, цен и ссылок (`npx tsx scripts/demo-catalog.ts` пересоздаёт его).

Импорт фида поставщика (YML/XML, как для Prom/Rozetka/Hotline) — только при наличии разрешения поставщика:

```bash
cd apps/server
npx tsx scripts/import-yml.ts feed.xml category-map.json "Поставщик"   # перезаписывает data/catalog.json
```

`category-map.json` сопоставляет категории фида с предметами дизайна: `{ "12": "sofa", "Ліжка": "bed" }`.

### Кухня-гостиная

При пожелании «Объединить кухню с гостиной» появляется зона «Кухня-гостиная»: перегородка убирается, обе комнаты
проектируются вместе. Зона недоступна, если стена несущая или на кухне газ (`designZones` в `design.ts`).

### 3D

Мебель — параметрические модели (`Furniture3D.tsx`) точно в размерах предмета; текстуры пола и стен рисуются в коде
(`textures.ts`), внешних файлов нет. Стены видны только изнутри, поэтому комнату видно и при полной высоте стен.
